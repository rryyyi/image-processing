# 仓库文档与基础维护设计

## 目标与读者

面向技术面试官、Agent 开发岗位招聘方和潜在使用者，使读者能快速理解 docrestore 解决的问题、实现方式、使用入口、实验依据及工程边界。以可验证的代码和结果展示工程能力。

## 已确认的现状

- 本地空目录已克隆 `https://github.com/rryyyi/image-processing.git`，当前为跟踪 `origin/main` 的 `main` 分支。
- 主包是 NumPy/OpenCV/SciPy 实现的本地文档图像修复工具，提供 Python API 和 Typer CLI。
- 流水线包含页面检测、透视矫正、光照恢复、可选增强、处理前后质量评估和失败警告。
- 每次文件处理可输出页面图、拼接图、manifest.json、effective_config.yaml 和可选中间图。
- 已提交真实配对数据的汇总指标、逐图指标、效果图、技术决策和研究参考。
- 当前未实现 LLM 调度、Agent 编排、MCP 服务、OCR 服务和在线部署。
- 原 README 引用了未入库的实验报告；场景示例中的 `-c` 与当前 CLI 参数声明不一致，应在文档中使用核实后的 `--config`。

## Approaches：展示方式

1. 仅扩写 README：改动最少，但使用入口、评测细节与协作规范容易堆在一个文件中。
2. **README + 少量专题文档 + 基础维护配置（推荐）**：首页便于快速理解，架构和评测细节可追溯，自动测试与协作模板增强可维护性。
3. 增加完整 Agent 平台：需要新产品设计、实现和评估，超过本次文档与简单维护范围。

用户已确认本设计，采用方案 2。

## 具体设计

### README

中文为主，保留英文项目名及常用技术术语，按以下顺序组织：

1. 项目定位、技术栈和真实可用的徽章。
2. 典型文档退化问题、适用场景和现有效果对比图。
3. 核心能力与 Mermaid 处理架构图。
4. 跨平台安装、单图修复、质量评估、场景配置与中间结果命令。
5. Python API、结构化输出文件和 Agent 工具接入方式说明。
6. 真实配对基准结果表，以及数据规模、硬件/计时和不可泛化的限制。
7. 项目目录、测试与实验入口、技术决策及参考链接。
8. 已实现能力、限制和后续方向。

Agent 岗位相关展示通过工具边界、参数配置、结果契约、可诊断输出、保守回退和评测方法展开；接入建议明确标注为示例或未来工作，不宣称已实现 Agent 系统。

### 配套文档与维护

- `docs/architecture.md`：模块职责、数据流、输出契约和接入边界。
- `docs/evaluation.md`：指标含义、现有结果、实验依赖与复现前提。
- `CONTRIBUTING.md`：开发安装、测试入口、提交和实验结果规范。
- `.github/workflows/tests.yml`：在 Linux/Windows 的受支持 Python 版本上安装主包与开发依赖并执行 pytest，避免依赖未入库数据或模型。
- `.github/ISSUE_TEMPLATE/` 与 `.github/pull_request_template.md`：最小可复现问题描述、改动目的和验证记录。
- `.gitignore`：补齐明确属于本地环境的凭据/构建产物忽略项（如确有需要）。

不擅自替作者决定开源许可证，不增加虚构的覆盖率、部署地址、性能承诺或荣誉标签。

## 验证与交付

- 使用 Python 3.12 创建本地环境，安装主包和测试依赖。
- 执行现有测试；核实 CLI 帮助、README 命令及 Python API 示例。
- 检查本地 Markdown 链接、引用图片、YAML 和 Git diff。
- 现有基准作为历史实验结果引用，不在缺少原始数据/权重时宣称重跑成功。
- 完成本地修改与验证后提供具体变更和验证结果；不使用强制推送，不改写历史。
- 用户当前已要求连接仓库并简单维护；实现完成后再确定远程发布动作及结果，优先保留可审核的提交。

## 范围

本次是小型文档与仓库维护，不改图像处理算法，不新增 Agent 运行时或服务。CI、文档布局及模板形式由助手按现有 Python 项目结构实施。
